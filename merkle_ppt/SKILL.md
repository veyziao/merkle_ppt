# Merkle PPT — 0.2.0

Follow the current user's explicit requirements first. This workflow is for Merkle decks; for a narrow edit preserve unrelated content. Before authoring, determine audience, purpose, language, evidence, scope and output. Structure the story and identify each slide's key message, content relationship and density. Distinguish facts, assumptions and proposals; never invent data, customer logos, case results or evidence.

## Fonts

Before creation ask the user to select English (Proxima Nova, Aptos, Arial) and Chinese (Microsoft YaHei/微软雅黑, PingFang/苹方), unless already specified. Check availability and ask for alternatives if unavailable. Default to Regular while retaining intentional emphasis; apply selected fonts consistently, maintain relevant reference size, alignment and character spacing, and inspect mixed-script rendering.

## Template and slide selection

Start every deck with the designated [Merkle PowerPoint Template.potx](assets/Merkle%20PowerPoint%20Template.potx) and create every slide using its actual master and appropriate layout. Preserve its lower-left logo and live lower-right automatic page number. Do not simulate inherited master components with manual duplicates. If the designated file is unavailable, request it; do not silently substitute a different template.

For every slide determine its purpose and select its category in [Slide Library.pptx](assets/Slide%20Library.pptx). Inspect candidate original pages, not just an index or screenshot, and choose a composition suited to the information relationship, density and audience. The 15 sections are Covers, Agenda, Dividers, Content Layouts, Approach and Process, Why Merkle, Team Member, Tables & Reporting, Pricing, Timelines & Phases, Sample Deliverables, Market Scan Slides, Single-Page Case Studies, Next Steps and Closing. Use varied suitable Content Layouts across the deck; avoid a single repeated layout. Keep a working page-by-page map of category, source page, rationale and intended visuals.

Divider is a chapter transition. When needed, use distinct complete picture-bearing slides from [DIVIDER IMAGES.pptx](assets/DIVIDER%20IMAGES.pptx), preserving image, composition and effects while replacing chapter text. Select by theme; if none matches exactly, choose randomly. Match chapter names and order to the agenda. Category header and sample ranges: Mobile Female 2/3–11; Mobile Male 12/13–18; Tablet Female 19/20–25; Tablet Male 26/27–30; Desktop Female 31/32–36; Desktop Male 37/38–42; Multi-Channel Female 43/44–47; Multi-Channel Male 48/49–51; Millennial 52/53–60; Gen Z 61/62–68; Baby Boomers 69/70–75; Travel 76/77–81; Retail 82/83–86; CPG 87/88.

Read source objects' actual and inherited theme/master/layout properties, not just appearance: position, dimensions, spacing, alignment, text insets, font, size, weight, underline, color, paragraph and line spacing, fill, transparency, outline, shadows, 3D, crop, geometry and rounding. Preserve meaningful visual hierarchy, composition and effects. Adjust size, spacing, element count and position to fit the new content without collisions or loss of legibility. If content overflows, select a better layout, simplify while preserving meaning, restructure or split slides before shrinking type. Read and follow green authoring notes and remove those notes from output; keep genuine content labels as appropriate.

## Images, icons and diagrams

When a layout needs an image, analyze its frame, visual purpose and crop; use actual Chrome screenshots for accurate real websites or interfaces and image generation for conceptual or atmospheric imagery as appropriate. Preserve aspect ratio, crop and reposition to fit without distortion, preserve relevant source rounding, shadows, 3D, geometry and placement, and keep the subject visible. Never leave a picture placeholder in a final deck. If an image is optional and unavailable, use an appropriate layout that does not require it. If actual visual evidence is essential and unavailable, disclose the gap; do not fabricate screenshots.

The library's distinctive tilted, layered 3D image treatment is suitable when fine image details need not be read; use large front-facing images when legibility matters. Read the actual source object's 3D rotation, depth, shadow and geometry, then verify the result.

Use icons appropriately across the deck without crowding or unnecessarily leaving the whole deck icon-free. Search [Merkle_icon.pptx](assets/Merkle_icon.pptx) and [its index](references/merkle-icon-index.json); inspect originals. Labels and suggested scenarios aid discovery, not strict limits: use a suitable metaphor when context makes its meaning clear. Check consistent size, baseline, spacing and alignment with text and frames. Generated custom icons must be PNG or SVG.

For diagrams, inspect [Diagram library](assets/Diagram%20library%20-%20Diagram%20Elements.pptx), select based on the real process, hierarchy, cycle or other relationship, and adapt original shapes, lines, colors, effects and spacing without copying sample business content. Select charts to match actual data and prefer editable native charts.

## Authoring and quality gates

Use native editable PowerPoint text boxes, shapes, connectors and tables. Put each continuous passage in one text box with automatic wrapping; never fake wrapping with multiple aligned text boxes. Preserve editability for native charts when appropriate. Do not substitute source visuals for actual evidence.

Render every slide and inspect typography, hierarchy, alignment, clipping, overflow, image cropping, icons, diagrams, accurate content, source formatting, and removal of authoring notes and placeholders. Review the full deck for consistent margins, titles, colors and image treatment, varied layouts, and agenda/divider consistency. Inspect the file's structural integrity, master/layout relationships, asset references and live page numbers, and when possible open it in PowerPoint and check for repair prompts. If a source effect or font cannot be reproduced, try preserving the source object or another implementation, verify the actual result, and disclose remaining affected slides and limitations. Do not claim validation that was not performed.

When a source library changes, verify its current sections, page numbers, objects and index against the source before use; update stale indexes where possible. If a required source is missing, say so and obtain it; never claim to have inspected it.
